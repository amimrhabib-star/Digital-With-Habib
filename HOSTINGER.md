# Publish on Hostinger

## A. Node.js Web App — ZIP or GitHub

In hPanel choose Websites > Add Website > Node.js Web App (sometimes labelled Deploy Web App). Choose Upload your website files and select this ZIP, or Connect with GitHub and select your repository. Use a plan supporting backend Express applications.

| Setting | Value |
| --- | --- |
| Framework | Express / Node.js backend |
| Root | Repository root, `.` |
| Node version | 22 or 24 |
| Install | `npm ci --include=dev` |
| Build | `npm run build` |
| Start | `npm start` |
| Entry file, if requested | `app.cjs` |
| Health endpoint | `/api/health` |

If there is only a build-command field, use `npm ci --include=dev && npm run build`. Keep data/, public/uploads/ and dist/ in the runtime. Do not publish only dist/client or select static Vite hosting. Leave the platform-assigned PORT unchanged.

Set these private runtime variables:

| Variable | Value |
| --- | --- |
| NODE_ENV | `production` |
| COOKIE_SECURE | `true` |
| APP_ORIGIN | Your exact HTTPS address, no trailing slash |
| ADMIN_PASSWORD_HASH | Value generated by `npm run setup` on your computer |
| STORAGE_DIR | Host-confirmed absolute private writable path preserved across redeployments |

Update APP_ORIGIN when changing from a temporary domain to your own domain. Ask Hostinger support to confirm a durable directory for your plan; the reviewed documentation does not establish one for every managed Node plan. If no durable path is available, use Option B. Do not store live data in a temporary build directory or public web root.

Deploy, then visit the new URL and /#/admin. Follow START-HERE.md to verify uploads, saving and restart/redeployment persistence.

### Add the files to GitHub

Use https://desktop.github.com/ because an included video exceeds GitHub's browser upload limit. Extract the ZIP, add this folder in GitHub Desktop, create a repository if prompted, commit and Publish repository with Keep this code private selected. package.json must be at the root. The supplied .gitignore excludes .env, dependencies, builds and runtime data. Do not commit private backup archives.

GitHub stores source; Hostinger runs the backend. GitHub Pages cannot run this app. Connecting the repository enables code updates via pushes; persistent data must survive those redeployments.

## B. Hostinger VPS — Docker with dedicated persistent volume

The included configuration is for a VPS with Docker Compose installed and ports 80/443 available. It runs the same app behind Caddy HTTPS. Existing proxies on those ports need integration rather than removal.

1. Point your domain's A record to the VPS IP. Open inbound TCP 80 and 443. Correct or remove conflicting IPv6 DNS records.
2. Upload/extract this ZIP to a private folder on the VPS, or clone your private GitHub repository there using your own repository credentials.
3. Generate your password using START-HERE.md. Create a private .env beside docker-compose.yml with these two lines, replacing both examples:

```dotenv
DOMAIN=your-real-domain.com
ADMIN_PASSWORD_HASH=your-generated-salt-and-hash
```

DOMAIN must be a hostname without https:// or any path. Restrict .env permissions with `chmod 600 .env`.

4. From that folder run:

```sh
docker compose config --quiet
docker compose up -d --build
```

5. Open https://YOUR-DOMAIN and https://YOUR-DOMAIN/#/admin. Caddy issues HTTPS after DNS is correct and the ports are reachable. If needed, inspect `docker compose logs --tail=100`.

For future code updates run `git pull --ff-only` then `docker compose up -d --build`. The `digital_with_habib_data` named volume holds content/uploads. Normal restarts and rebuilds retain it. Do not delete it or run `docker compose down -v`. Back up before deleting/resetting a VPS; a volume does not survive destruction of its host.

Docker was unavailable in the preparation environment, so verify this Compose deployment on your VPS. The standalone Node build, admin APIs, uploads and restart persistence were tested separately.
